# Spoor 2 — external evidence authenticity decision (2026-11-11)

**Decision: no external source attestation is implemented. No admission or trading changes.**

## Evidence tiers and what each proves

| Tier | Artifact | Established | Not established |
| --- | --- | --- | --- |
| 0 | Caller-supplied metadata | Claimed provider, hostname and timestamp | Authenticity, freshness, independence |
| 1 | Locally hashed bytes | Exact digest of bytes provided to the function | Who obtained bytes, whether a provider served them |
| 2 | Parsed DNS packet | Question, RR metadata and syntax within configured limits | Resolver authenticity, DNSSEC, IP ownership |
| 3 | HTTPS capture with verified peer | Authenticated TLS endpoint and captured response, subject to independently verified connection metadata | Market-data provenance or DNSSEC by itself |
| 4 | Independently corroborated source | Evidence from distinct provider-controlled channels, with original immutable receipts and checked identities | Guaranteed financial accuracy or profitable trade |

Existing `audit_external_capture` establishes only tier 1, despite a field called `source_url`. Existing `audit_eu_source_separation` compares self-declared provider/family labels and cannot prove tier 4. The DNS evidence inventory establishes tier 2 on caller-supplied bytes, not DNSSEC.

## Required admission boundaries

- Never treat two different strings in `provider_id`, `source_family` or `source_url` as independent proof of two external sources.
- Capture response bytes, request parameters, actual verified TLS peer/certificate identity, redirect chain, UTC capture time, provider response identifiers and content digest in a receipt generated by the capture process itself. Distinguish observer clock from provider timestamp.
- Require an independently controlled provenance mechanism and verify its authenticity before promoting an observation to externally attested status. A caller-created signature is not independent attestation.
- Verify that a technical-level source is genuinely independent of the broker quote source, including corporate/data-vendor lineage, not merely URL hostname.
- Preserve immutable raw evidence and deterministic replay tests; explicitly block missing, conflicting, stale, truncated or unauthenticated evidence.
- Keep DNSSEC validation and HTTPS/TLS peer verification separate: neither one alone authenticates a market-data publisher.
- Require independent review of a concrete real capture and threat model before considering live integration.

## Next implementation gate

Prefer an offline **receipt consistency checker** that compares immutable hashes and independently recorded request/response fields across existing artifacts. It must return `source_attested=false`, `dnssec_verified=false`, `trade_ready=false` regardless of consistency. Do not create another self-asserted approval gate, add trusted keys, make network calls or alter live workflows.

Current decision: **RESEARCH_ONLY / EXTERNAL_ATTESTATION_MISSING / NO_TRADING_ADMISSION**.
